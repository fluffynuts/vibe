# Headless: reaching its page from another machine, and noticing a logged-out agent

- **Status:** accepted, built 2026-10-15 (steps 1 and 2 of the plan "what's left for headless"); the earlier headless work (steps 1–3 of the
  plan before it, committed 2026-10-14 as 41fd67e) is described in the readme's headless section. What was left over is in
  `docs/plan-headless-nice-to-have.md`.
- **Decided:** 2026-10-14/15, with the user, who reached the page from another machine with the ssh line this produced.
- **Came from:** `docs/plan-headless-remaining.md`, now deleted: `git show 7559779:docs/plan-headless-remaining.md`.

## Context

A headless vibe (`vibe --headless`: the sandbox and its companion page, with no terminal attached) is mostly useful from elsewhere, over SSH.
Two things made that awkward: the page only answers on its own port (its Host check wants `localhost:<its port>`) and embeds the clipboard
and diffity pages by their own ports, so a forward has to keep every port's number; and nobody sees the agent's login prompt, so a prompt
from the page to a logged-out agent would just fail.

## Decision

1. **`vibe --info` says how to reach the page from another machine.** When the sandbox exists and a companion port is recorded, it prints the
   page's address with its token (and whether a vibe is serving it now, via `companion.Running`) and an `ssh -N -L …` line that forwards the
   page's port and each published port (`inst.CompanionPort`, then each `inst.Publish[].HostPort`), **each keeping its number**. The forwards go
   to `127.0.0.1`, not `localhost` (which can be `::1`): `sbx ports --help` says sbx publishes without a host IP on 127.0.0.1 alone. The user
   and host are the current user (a Windows `DOMAIN\` stripped) and `os.Hostname()`; another machine may know this one by another name, so the
   line is a starting point, and the readme says so. A headless start points at `vibe --info`. A pure helper builds the line (`sshForwarding`),
   unit-tested, and the rows are tested including "no page yet" showing neither.
2. **A logged-out agent is detected, and said.** Found by trying it: a logged-out `claude -p` turn ends with an assistant line marked
   `error: "authentication_failed"` ("Not logged in · Please run /login") and an error result, and `claude auth status` prints JSON with
   `loggedIn`, exiting 1 when logged out. The headless vibe checks each time its sandbox starts (`src/vibe/login.go`) and warns **only when
   certain**: logged out, with sbx's `SBX_CRED_ANTHROPIC_MODE` none or unset (read from the container's environment, which `su -` drops),
   because another mode may be sbx supplying the credentials. The page's note on such a turn (in `app.js`) says what to do: `vibe` in the
   folder, in a terminal, to log in.
3. **No periodic check that restarts a stopped sandbox** (dropped, 2026-10-15). sbx stopping idle sandboxes is wanted; the page keeps its
   sandbox awake while it is in view, and so does the page's server while the agent is at work (answering, or with something it left running:
   a review page). Found when a review page in another tab died when sbx stopped the sandbox under it. A new prompt still ends what the last
   turn left running, review servers included.

## Consequences

- Remote use is a command to copy, not transparent: the user runs the `ssh` line on the other machine.
- The warning is silent when unsure, so some logged-out cases are only found when a turn fails.
