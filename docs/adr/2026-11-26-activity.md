# Activity: time per repository and branch, for timesheets

- **Status:** accepted, built 2026-11-26 on `feat/activity`. Not yet tried by hand, nor dog-fooded (the plan's step 4: the gaps and the
  estimate are to be adjusted from use).
- **Decided:** with the user, 2026-11-26.
- **Came from:** `docs/plan-activity.md` (never committed), which keeps the want, the user's decisions and the WakaTime notes.

## Context

The user fills in a timesheet once a day and needs the day's time split per **repository and branch**, with a few lines on what was done
in each. WakaTime gives time per project only; their own `show-commits-for-today` gives commits but no time. The ratios are what matter.

## Decision

**An Activity tab**, on every page (the Profiles page too), covering every folder vibe has opened: the sandboxes vibe has records of, and
every folder in the activity log, so a day still shows after its sandbox is deleted. No other folder is looked at.

**Evidence**, each a mark of "work on repository R, branch B, at time T":

- **Vibe's own log**, written on the host while a sandbox's page runs: `~/.vibe/activity/<YYYY-MM-DD>/<sandbox>.jsonl`, a JSON line
  `{at, folder, repo, branch, kind}` each, one file per sandbox so two companions never write to one. Kinds: a prompt sent (the
  conversation, a review's Ask or Submit), the agent working (each minute **while a turn runs**: tasks left running after it cost
  nothing, and aren't marked), the user on the page (keys, clicks, wheel; said at most once a minute), a review action, and the folder's
  git status changing (seen by the page's polls). At most one mark of a kind on a branch a minute. The repository is named from origin
  (`activity.RepoName`), read every five minutes.
- **Git, after the fact:** each local branch's reflog (commits, merges, rebases, resets, its creation), and HEAD's for checkouts and for
  what a rebase was onto. Read **with go-git in the review helper** (`review.History`), never with git: the sandbox can write the folder's
  `.git/config`, and git would run what it names on the host. Reflogs are read from their end, at most 4 MB each.

**From marks to time** (`activity.Summarise`, pure, table-tested):

- A mark stands for the minute after it; marks on a branch no more than 15 minutes apart join into one **measured** stretch.
- Git's events on a branch no more than an hour apart count in full; the first of a run counts 15 minutes before it. **Estimated.**
- Measured time covers estimated time on the same branch: it counts once, as measured. Branches worked on at once each count in full.
- The day is local midnight to midnight; a stretch is cut there.
- Each branch's total is rounded **up** to the step (15 minutes, half an hour, an hour), so any work at all is at least one step: the
  cost of switching to it. One setting for all of vibe: `activityRounding` in `~/.vibe/settings.yaml`, half an hour unset.

**Bullets** (`activity.FromHistory`): the first line of each commit by the user (author email as `user.email` says in the repository,
else the user's git config; every commit when there's none) **authored** that day, so a rebase doesn't bring last week's commits into
today. A rebase is one event and one bullet, "rebased onto master" (`origin/` dropped); a merge, "merged master" (a fast-forward
too); a pull is an event and no bullet; an amended commit replaces its bullet. The same text on a branch is one bullet.

**The page:** `<` and `>` step through the last week, the day returns to today; each branch a row of repository, branch, decimal
hours, a meter of its share of the day and "~estimated" if any of it is, with its bullets under it; a row opens to its stretches, the
measured and estimated time before rounding, and its folders. **Copy** gives
`[repo]` / `  [branch] 2.5` / `  - bullet` lines. The tab asks again every 15 seconds while open (each folder's git is read at most once
a minute, its status every 15 seconds), and redraws only on change, so an opened row stays open and focus stays put. What can't be read
(a folder's git, a cut-short log line) is listed, not hidden.

**Needs attention** is git's state **now**, whichever day is shown: uncommitted changes, "N commits not pushed", "never pushed" (no
upstream). Before saying commits aren't pushed, GitHub is asked in the background (the host's gh, in a folder of its own, for the
branch's head: `ghRemoteHead`): a branch pushed by URL, whose local copy of the remote is stale, is then left out, and a count is from
GitHub's head when the folder has it. "Checking with GitHub…" shows meanwhile; without gh, the local count stands.

## Consequences

- Git marks come only while a page polls; outside vibe, time is git's estimate, from commits and checkouts.
- The log grows by a few kilobytes per sandbox per active day, and nothing removes it yet.
- A branch with time but no commits shows no bullets; Needs attention is where uncommitted work is warned about.

## Not built

- Pruning the log past the week shown.
- Catching edits outside vibe that never become a commit (a watcher running all day); the estimate stands in for now.

## Not verified

- By hand: the tab on a real day's work, the marks of a real turn, Copy into a timesheet, and the GitHub check on a branch pushed by URL.
- The 15-minute join, the hour gap and the 15 minutes before a run are the plan's first guesses, to be adjusted from use.
